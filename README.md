# 旅居社区长期协约

本项目管理村落院落、房间、公共资源与长期旅居协约。使用方式包括整院、房间和会员换住，时间范围为两周至一年。维修封闭、临时离村与跨村换住都会改变可用权益，但不删除原协约。

村民、运营方和旅居者共同确认押金、服务工时及收益分成。规则按生效版本结算。共享菜地、书屋和活动空间分别记录容量，身份与健康材料使用限时授权，不进入普通社区档案。

## 结构

- `community/model.py` — 领域模型：日期为 ISO 字符串，金额为分，比例为基点（万分比），居住区间为半开区间 `[start, end)`。
- `community/store.py` — 领域核心 `CommunityStore`：协约生命周期、超卖防护、跨村换住、版本化结算、隐私授权、JSON 快照持久化。
- `community/api.py` — `/api/*` 路由，状态全部在 store 中。
- `service.py` — 运行入口：`/health` 健康检查 + 领域 API。

## 关键规则

- **协约生效**：创建后为待确认，村民 / 运营方 / 旅居者三方确认齐全才生效；生效时锁定当日生效的结算规则版本并计算押金，老合同不被新政策追溯改价。
- **超卖防护**：生效协约与维修封闭共同占用房间权益；新协约、整院、换住与之重叠即拒绝。待确认协约不占用权益，生效前做最终校验。
- **跨村换住**：两侧协约在同一锁内原子创建，任一侧不可用则整组不落地。
- **临时离村**：权益保留、容量不释放、照常计费；维修封闭夜不计费。
- **结算**：按协约锁定的规则版本逐月结算，每条分成记录所采用的规则版本；同一（协约， 月份）幂等，停机重跑不产生重复单。
- **公共资源**：菜地、书屋、快递代收等按日容量控制，占用必须登记理由；共享活动容量有限，满员拒绝。
- **隐私授权**：身份 / 健康材料仅凭限时授权查看，到期自动收回（访问时校验 + 清扫兜底），查看行为留痕于事件日志。
- **恢复**：每次变更写 JSON 快照（临时文件 + 原子替换），重启后整体恢复，事件序号连续。

## 运行

```bash
python3 service.py --check              # 基础自检（含领域核心冒烟与恢复）
python3 service.py --port 8000          # 启动服务（默认数据文件 community_data.json）
python3 service.py --port 8000 --data /path/to/data.json
npm test                                # 全部测试（契约 + 领域 + API）
```

## 验收场景

`test_domain.py::AcceptanceTest` 覆盖：两村同时办理换住 → 跨月结算（8 月结完后模拟停机）→ 从快照恢复 → 新政策发布后老合同仍按 v1 结算 → 核对某天各房间使用权、公共资源占用理由、每笔分成采用的规则版本与授权收回留痕。

主要查询接口：

- `GET /api/rights?courtyard_id=…&day=…` — 某院落某天各房间使用权（空闲 / 占用 / 封闭及理由）
- `GET /api/occupancy?day=…&village_id=…` — 公共资源占用明细与剩余容量
- `GET /api/settlements?agreement_id=…` — 结算单与分成规则版本
- `GET /api/events` — 全部领域事件（审计留痕）
